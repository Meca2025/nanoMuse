# nanoMuse 0.1.17 · Doorstep

Start without an API key. The first screen now says *Start now*: a phone number or an e-mail address, a code, and the agent has a model to talk to — a starter allowance on nanoMuse Cloud, a small open-source relay that anyone can run. Bringing your own key is the other door on the same step and works exactly as before.

## Added

- **Start now.** Sign up with a phone number or e-mail on the first screen (or later in *Settings → nanoMuse Cloud*). The app gets a provider called *nanoMuse Cloud*, its models, a model group with the recommended chat model — set as the default only if you had none — and the relay's picture model for the avatar, if none was set. Your own providers stay as they are, and the relay's models can share a group with yours.
- **Settings → nanoMuse Cloud.** Who is signed in (a masked hint, never the number), how much of the allowance is left, today's use against the daily cap, the provider's own page, and *Sign out*, which revokes this phone's key at the relay and removes the provider. The allowance belongs to the number: signing in again gives a new key for the same account, not a second grant.
- **The relay** (`cloud/` in the repository). FastAPI + SQLite; codes by Aliyun SMS or SMTP; identifiers kept only as salted hashes with a display hint; an OpenAI-shaped proxy for chat (streaming, usage forced on) and pictures (translated to Model Studio's native image API); a ledger charged from the upstream's own usage, a daily cap, a per-minute limit; admin top-up by phone number or account id; Dockerfile, Caddy compose and tests. [docs/cloud.md](../cloud.md) has the details and how to run one of your own.

## Changed

- The first-run step 1 reads *Connect a model* and offers both doors; the subtitle no longer assumes a key of your own.
- [privacy.md](../privacy.md) gains a paragraph on what the relay keeps (hashed identifier, key hashes, token counts) and does not (message content).
- versionCode 18; installs over 0.1.16 without losing data.

## Not in this version

- The relay address is a setting only in debug builds; release builds talk to `cloud.nanomuse.cn`. A user-facing setting for a relay of your own is next.
- Non-mainland phone numbers are accepted as identifiers, but the SMS sender only covers `+86`; use e-mail for the rest.
- The allowance is a starter grant. What comes after it — a top-up, a subscription, or nothing but your own key — is not decided in this version; the ledger and the admin endpoint are ready for any of them.

## Known issues

- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.
- A full turn of the agent carries its system prompt, memory and tool list, so one message costs on the order of ten thousand tokens of the allowance; the flash model is charged at 0.3×.

## Install

Download `nanoMuse-0.1.17-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.17-arm64.apk.sha256`.
