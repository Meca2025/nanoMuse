# nanoMuse 0.1.25 · Mirror

One name and one face for the account, on every device; a Stop button while the hands work the computer; light by default; a desktop app that starts, and says why when it does not; fewer words on every screen.

**Free, open source, non-profit — open source, built together: a personal agent for all.** Sign in with a phone number or an e-mail and the model comes with a free allowance, paid by the developer — the account page says how much is left and how it grows; when it is gone, bring your own key, with a step-by-step guide. Messages are not stored unless you choose to contribute them; nothing is sold; delete the account whenever you like. Report a bug, ask for a feature, send a pull request — every one brings a personal agent within everyone's reach. [Open an issue](https://github.com/nano-muse/nanoMuse/issues/new/choose) · [send a pull request](../../CONTRIBUTING.md) · [Discussions](https://github.com/nano-muse/nanoMuse/discussions) · [star the repo](https://github.com/nano-muse/nanoMuse).

## What changed

- **One name and one face for the account** (relay 0.7.0). The agent's name and look — the dragon, an emoji on a colour, or a face drawn in the avatar studio with its five stills — live with the account (`GET` / `PUT /v1/me/profile`, last writer wins) and follow you to every device: a rename or a new face on the phone is on the desktop within a moment, and the other way round. The relay tells the devices on the hub, each fetches the new revision and wears it; the first device to sign in seeds an empty profile with what it has. Nothing else travels — keys, providers and settings stay where they were entered; the privacy note says what the relay now keeps.
- **A stop button on the desktop stage.** While the hands work the computer, the pill at the top of the screen has *Stop* — a click ends the run the way the shortcut does — and the stage lets clicks through everywhere else, so the desktop stays usable underneath.
- **Seven avatar styles on the web and the desktop** — 3D toy (Muse's), flat, 3D clay, watercolour, pixel, line, sticker — the phone's list, with the same words to the model, so a face described on either device comes out alike. *Settings → Draw a new one* shows the chips and starts the studio straight away.
- **Light by default.** The web and desktop app, nanomuse.cn/web's sign-in page, the relay's console and the site are light unless you choose otherwise; *Settings → Appearance* has *Light*, *Dark* and *Follow the system*, and the site's footer has a toggle.
- **The runtime opens its port first and finishes starting behind it.** A slow step used to leave `/api/health` unreachable and the desktop app waiting for a port that never opened; the services now start in the background and `/api/health` says `starting: "<step>"` while they do. If the app is still not serving after 20 s and 60 s a watchdog writes where every thread is to the log. The desktop shell's error box tells the causes apart — a runtime that answered but never came up, a `config.toml` that really does not parse (that message used to be shown for every failure), a Linux runtime refused for its glibc (install 0.1.24 or newer; those are built in Debian 11) — and `netstat` on Windows is read with a buffer large enough for machines with many sockets.
- **The relay's certificate is checked with a bundle the bundled runtime has.** The desktop runtime on macOS could not verify `cloud.nanomuse.cn`'s certificate and the Devices page said the account had turned this computer away. The runtime now points Python at certifi's bundle when the system has none to offer, and a certificate failure is reported as a disconnect with its reason.
- **The sign-in page fits a landscape window.** In the desktop app and a wide browser the words sit on the left and the form on the right; a phone keeps the single column. The form says less.
- **Your own key is a step after sign-up, and a row in Settings.** After a new account the web app asks the third question the phone asks — *Which model answers?* — and while the account's model answers, *Settings → Model* shows *Use my own API key*.
- **Pictures are queued, not refused** (relay 0.6.3). The image provider allows only a couple of pictures at once and answered the studio's four with `429 Requests rate limit exceeded`; the relay now draws through a gate and retries with growing pauses, the runtime's studio draws two at a time and waits a 429 out, and the card says *The image provider is busy right now — try again in a minute* when it still fails.
- **A number the SMS sender cannot reach is told so at once** (relay 0.6.1). Codes reach mainland China numbers only for now; elsewhere, sign in with an e-mail address — every sign-in form says so instead of promising a code that never comes.
- **Fewer words on every screen.** The Devices, Account, Connections and Settings screens of the web and desktop app, and the phone's welcome, Cloud, Devices, PC, Hands, coding and media pages, keep every control and lose the paragraphs around them: one line under each heading, avatar tiles the size of a thumb, a name field without its hint and counter, Cloud fine print in one sentence.

## Install

| | |
|---|---|
| Browser | [nanomuse.cn/web](https://nanomuse.cn/web/) — a phone number or an e-mail |
| Android 8.0+, arm64 | `nanoMuse-0.1.25-arm64.apk` — same signing key, installs over 0.1.24 (versionCode 26); `sha256sum -c nanoMuse-0.1.25-arm64.apk.sha256` |
| Windows 10+ | `nanoMuse-Desktop-0.1.25-win-x64.exe` (the app) · `nanomuse-desktop-terminal-0.1.25-windows-x64-setup.exe` (terminal) |
| macOS 12+ | `nanoMuse-Desktop-0.1.25-mac-arm64.zip` / `-mac-x64.zip` (unzip, drag to Applications) or the `.dmg` (the app) · `nanomuse-desktop-terminal-0.1.25-macos-arm64.pkg` / `-x64.pkg` (terminal) |
| Linux x64 | `nanoMuse-Desktop-0.1.25-linux-x64.AppImage` / `.deb` (the app) · `nanomuse-desktop-terminal-0.1.25-linux-x64.deb` / `.tar.gz` (terminal) |

GitHub's own downloads are the fastest source from China too in our measurements; if they fail where you are, the same files are on [nanomuse.cn/dl/v0.1.25/](https://nanomuse.cn/dl/v0.1.25/) within fifteen minutes. The desktop installers are not notarised: on macOS open it once from System Settings → Privacy & Security → *Open Anyway* (or right-click → *Open*), on Windows click *Run anyway*. `SHA256SUMS-desktop-app.txt` and `SHA256SUMS-desktop-terminal.txt` list every checksum. The installers arrive a little after the APK — CI builds them from the tag.

### 变了什么

- **一个账号，一个名字，一张脸**（中转 0.7.0）。智能体的名字和形象——小龙、彩色底上的 emoji，或在形象工作室里画出来的那张脸和它的五张静态图——存在账号里（`GET` / `PUT /v1/me/profile`，后写的生效），跟着你到每台设备：手机上改个名、换张脸，桌面版片刻之后就一样，反过来也是。中转通知 hub 上的各台设备，各自取回新版本换上；第一台登录的设备会把自己的样子填进空的账号。别的都不走这条路——key、服务商和设置留在原来输入的地方；隐私说明里写了中转现在保存什么。
- **桌面 stage 上的「停止」。** Hands 操作电脑的时候，屏幕顶部的胶囊里有「停止」，点一下就和快捷键一样结束这一轮；其余地方点击都穿透，桌面照常能用。
- **网页和桌面版的七种画风**——3D 玩具（Muse 的那种）、扁平、3D 黏土、水彩、像素、线描、贴纸——和手机上同一份列表、同样的提示词，在哪台设备描述出来的脸都一样。「设置 → 画一个新的」直接显示画风并开始。
- **默认浅色。** 网页和桌面版、nanomuse.cn/web 的登录页、中转控制台和官网都默认浅色，除非你自己选深色；「设置 → 外观」里有「浅色」「深色」「跟随系统」，官网页脚有切换。
- **运行时先开端口，再在后面启动其余部分。** 以前某一步慢了，`/api/health` 就一直不通，桌面版等一个永远不开的端口；现在各项服务在后台启动，`/api/health` 期间会说 `starting: "<步骤>"`。20 秒和 60 秒后还没起来，看门狗会把每个线程在哪写进日志。桌面壳的报错框能分清几种情况——运行时有回应但没起来、`config.toml` 真的解析不了（以前每种失败都显示这句）、Linux 运行时因 glibc 太旧被拒绝（装 0.1.24 或更新的版本，它们在 Debian 11 里构建）——Windows 上读 `netstat` 的缓冲区也放大到了多连接机器够用的程度。
- **用运行时自带的证书链验证中转。** macOS 上的桌面运行时验证不了 `cloud.nanomuse.cn` 的证书，设备页却显示账号「拒绝」了这台电脑。现在系统没有证书链时运行时用 certifi 的那份，证书失败会按断开连接报告并写明原因。
- **登录页适配横屏窗口。** 桌面版和宽浏览器里文字在左、表单在右；手机还是单列。表单上的话也少了。
- **自己的 key：注册后的一步，设置里的一行。** 新账号之后网页版会问手机上问的第三个问题——「谁来回答？」——用账号自带的模型时，「设置 → 模型」里有「用我自己的 API key」。
- **生图排队，不再拒绝**（中转 0.6.3）。图像服务商一次只允许一个账号画两三张，工作室一次画四张就被回 `429 Requests rate limit exceeded`；现在中转通过一个闸门排队并逐步加长间隔重试，运行时的工作室一次画两张、遇到 429 等一等，还是不行时卡片上会写「图像服务商现在很忙，一分钟后再试」。
- **短信发不到的号码，马上告诉你**（中转 0.6.1）。验证码目前只支持中国大陆手机号，海外请用邮箱登录——每个登录表单都这么说，而不是承诺一条永远收不到的短信。
- **每个页面的字都少了。** 网页和桌面版的设备、账号、连接、设置页，手机上的欢迎、Cloud、设备、电脑、Hands、编程助手和媒体页，功能一个不少，周围的大段说明去掉了：每个标题下一行话，形象图块只有指头大，名字输入框不再有提示和计数，Cloud 的小字一句话说清中转保存什么。
